Projet : DecoAR
Unity : 6000.6.6f1
Type : AR mobile + UI + ScriptableObject + AR Foundation
Langage : C#
Modules : M1, M3, M4

Contexte du besoin
- Le projet DecoAR existait déjà avec M1 et M4.
- Le module M3 manquait.
- Le besoin était d’ajouter un catalogue produit dans M3, permettre la sélection du produit, puis transmettre la sélection au module M4 via GameManager.
- M4 attend un prefab produit et une taille réelle de produit (sizeCm).
- M3 est une couche de sélection, M4 est la couche d’AR placement.

Architecture visée
- M3_ProductCatalog : ScriptableObject avec une liste de produits.
- M3CatalogSelector : lit le catalogue, instancie les boutons produits, et envoie la sélection au GameManager.
- GameManager : stockage global de l’état partagé entre modules.
- M4PlacementGate : lit le produit sélectionné dans GameManager et l’instancie sur une surface détectée.

Fichiers importants
- Assets/DecoAR/Core/Scripts/GameManager.cs
- Assets/DecoAR/M3_ProductCatalog/Scripts/M3ProductCatalog.cs
- Assets/DecoAR/M3_ProductCatalog/Scripts/M3CatalogSelector.cs
- Assets/DecoAR/M3_ProductCatalog/Data/M3_ProductCatalog.asset
- Assets/DecoAR/M4_AR/Scripts/M4PlacementGate.cs

Etat attendu
- Quand on clique sur un produit dans M3, il doit :
  1. changer le texte M3_SelectedText
  2. appeler GameManager.SelectProduct(productId, prefab, sizeCm)
  3. stocker le produit sélectionné pour M4
- Quand M4 démarre / lit le GameManager, il doit récupérer le prefab sélectionné et le placer sur une surface.

Problème réel actuel
Le problème n’est plus dans la logique C#.
Le problème est visuel / UI / placement / raycast.

Les boutons existent et ont des listeners, mais ils sont placés hors du champ visible / hors du panel, ou le panel parent capte les clics.

M3_ProductPanel est probablement :
- mal positionné
- mal dimensionné
- mal aligné
- ou l’image du panel bloque les raycasts

Le bouton généré est probablement en dehors du panel visible, avec des coordonnées de RectTransform anormales (ex. left/top négatifs, ou hors des limites visibles).

Le bouton prefab doit être correctement configuré :
- Image.raycastTarget = true
- Button.interactable = true
- RectTransform normalisé / visible
- le panel parent doit avoir raycastTarget = false pour ne pas bloquer les clics

Le parent panel doit être un conteneur UI propre :
- ajouter Vertical Layout Group
- aligner les enfants
- éviter que le panel absorbe les clics
- garder les boutons visibles dans le viewport

Le bug observé
- On peut voir dans l’Inspector que les boutons sont présents.
- On peut voir les logs de listeners ajoutés.
- Mais aucun log [M3] Click reçu: ... ne s’affiche.
- Donc aucun clic n’atteint réellement le bouton.

Conclusion
- Le code M3 est fonctionnel au niveau logique.
- Le vrai bug restant est un problème de layout UI / raycast visuel.
- La prochaine correction à faire est de régler le panel et le RectTransform du bouton généré :
  - M3_ProductPanel = container, raycast false
  - M3_ProductButton_Prefab = bouton cliquable, raycast true
  - Vertical Layout Group sur le panel
  - supprimer les anciens boutons de test
  - relancer Play
  - vérifier enfin le log [M3] Click reçu: ...
